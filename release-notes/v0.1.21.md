# AgentTeams v0.1.21

- Acceptance criteria can now be **waived** instead of force-failed. A member submits `status: "waived"` with evidence naming the reason — a check that is already red on the baseline, or one no measurement exists for — and the criterion counts as covered. The task is flagged, and Delivery stays blocked with `<id> has unconfirmed waivers` until a `review` task confirms the waiver with an explicit `waiverConfirmation`. `reviewPolicy.allowWaivers: false` forbids the mechanism outright. This closes the incident where an honest implementer refused to write "passed" against an externally red check and the lane was marked failed even though its work was correct.
- Acceptance criteria may be written as `{ text, mode: "no_regression", baseline }`. A `no_regression` criterion passes on "identical to the named baseline" rather than on "green", and its evidence must name the baseline.
- Removed the list-length fallback that accepted **any** same-length all-pass report as satisfying the contract. Criteria and commands are now matched by normalized text (whitespace collapsed, trailing punctuation dropped), and a failure lists every uncovered criterion by name instead of returning a bare rejection.
- Scope-overlap serialization is transitive. The check skipped only direct dependencies, so a replacement task whose whole downstream subtree still pointed at the task being replaced was refused with "inScope overlaps …; serialize these tasks" and the captain had to cancel the descendants first. It now walks the dependency closure in both directions, while a merely shared ancestor still counts as a real conflict. The dead `pending-new` bypass is gone.
- Delivery no longer reports a cancelled task's leftover `changedPaths` as an unaudited path; the path audit follows completed work only, so dead lanes stop polluting the report.
- A profile that nests a key wrongly now gets the fix, not just the rejection: `profiles.material.requiredReviewers is unknown at this level; requiredReviewers belongs under reviewPolicy (profiles.material.reviewPolicy.requiredReviewers)`. The near-miss suggestion is unchanged, and nested scopes (members, tasks, fallbacks) are checked too.
- New: `node scripts/doctor.mjs --profiles <config.json>` lints every configured profile's key structure without booting a host or reading credentials.
- The activity panel gained three read-only views over the same snapshot: **Phases** (columns by declared phase, otherwise by dependency level, with edges drawn between columns), **Agents** (one swimlane per member, left to right in execution order, blocked chips dimmed with the blocking task in the tooltip) and **Queues** (who holds what, what is next, and the grouped idle reason — `blocked by t5`, `no claimable task`, `all work settled`, `waiting to review tX`). The chosen view is remembered per browser.
- Internal: the task-status transition table exists once (`src/state.ts`); the completion gate reads it instead of keeping a second copy that could drift.

## Compatibility

The supported Harness matrix is unchanged: recommended `0.1.5-rc.1`, plus `0.1.2-rc.1`, `0.1.2-alpha.5`, and `0.1.2-alpha.2`.

`team.json` files written by earlier versions load unchanged: `waived`, `no_regression` criteria, `hasWaivers` and `waiverConfirmation` are all optional on read, and a criterion given as a plain string keeps its meaning.

The tool signatures are unchanged in this release. **Upcoming in 0.1.24:** every team-scoped tool will take a mandatory `team_id`, except `agent_teams_create` (which returns it) and `agent_teams_status` called with no arguments (which lists the caller's teams). A team created earlier keeps working, because its existing id *is* the `team_id`.

Scope control is still a completion-time audit, not host write interception. Widening the contract after a task finished (`accept_paths`) and replacing a failed task without cancelling its descendants (`supersede_task`) ship in `0.1.23`.

Update the plugin in your existing profile, then restart Harness:

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.1.21
```

See [release verification](https://github.com/NanmiCoder/dsh-agent-teams/tree/main/docs/releases/v0.1.21) for real-provider scenarios, evidence boundaries, and publication results.
