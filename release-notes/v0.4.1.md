# AgentTeams v0.4.1

A client-only follow-up to 0.4.0, requested by the owner the same day: **the overall
progress block now understands phases.**

- **One bar, split into the plan's phases.** When the plan declares phases, the bar is one
  zone per phase instead of a single fill: a phase takes the share of the width its size
  earns it, and each zone is filled with **that phase's own percentage** — Φ0 at 100 % reads
  full, Φ1 at 62 % reads two thirds, an untouched phase stays empty. Zone colours cycle, so
  the columns are telling apart at a glance.
- **The team's percentage gets its own line.** `58% · 18/36` sits under the bar, so the
  phase-by-phase reading never costs the overall number.
- **The legend names every phase**: `Φ0 — recon 100% · 6/6   Φ1 — build 62% · 8/13
  Φ2 — light 33% · 4/12   unphased 0% · 0/5`, each with the same colour as its zone.
- A plan **without** declared phases keeps the three-colour split by origin from 0.4.0 (the
  original plan / what was added while it ran / what arrived after it settled), so nothing
  the previous release explained stops working.

The percentages are the host's own numbers (`percentByKind` or `percentEqual`, whichever the
reader's mode button selects) — the panel only draws them, exactly as it draws the team's
overall percentage.

## Compatibility

The client bundle is the only thing that changed: no state, tool, schema, profile key or
quality gate moved. A team's `plan.phases` is what drives the split; a plan without declared
phases is unaffected. The supported Harness matrix is unchanged (recommended `0.1.5-rc.1`).

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.4.1
```

Then refresh the page — a browser that already has the panel open keeps the old bundle until
it reloads.

See [release verification](https://github.com/WhiteWh/dsh-agent-teams/tree/agent-teams-hardening/docs/releases/v0.4.1) for the verification matrix, the artifact digest and the deployment record.
