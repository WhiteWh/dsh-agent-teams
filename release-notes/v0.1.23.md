# AgentTeams v0.1.23

This release makes the captain's contract editable and a red lane recoverable, and closes
the last inert switches in the quality gates. New statuses: **`awaiting_scope_review`** and
**`superseded`**. The tool set grows from 14 to 18 (four new tools).

- **The whole contract is amendable, and a failed lane retries.** `agent_teams_amend_task`
  now covers `deliverables`, `nonGoals`, `reviewedTaskId`, `subject` and `description` as well
  as the original five fields, amends the brief of a `kind=work` task (`subject`,
  `description`, `deliverables`, `nonGoals`), and accepts a **`failed`** task — retrying a red
  lane is the first step of recovery, not a rewrite of history. `reviewedTaskId` must name an
  existing `implementation`/`repair`/`verification`/`integration` task. The shared transition
  table legalizes the `failed → pending` move that `agent_teams_reassign_task` always
  performed through `invalidateTaskAttempt`, so `transitionError` and the completion gate stop
  disagreeing with the tools. A **`force: true`** amendment overrides the post-review freeze
  and marks the passing verdict **`stale`**, so the changed contract must be reviewed again
  (`stale` is durable but never offered in the member-facing `update_task` enum).
  `agent_teams_status` prints `revised ×N` for an amended contract.
- **`agent_teams_supersede_task` replaces a lane that will not finish.** Captain-only, atomic
  under the team lock: the replaced task becomes `superseded` with `supersededBy`, loses its
  capability and `changedPaths` (its `output` stays as history), every non-terminal dependent
  is redirected to the replacement, and every non-terminal review/repair contract that pointed
  at it is retargeted. The replacement is an existing task id or a task created in the same
  call (inheriting `kind`, `round`, `sourceTaskId`, `coverageOf` and, by default, the replaced
  task's dependencies). A replacement that transitively depends on the task it replaces is
  refused — that would build a dependency cycle. A dependency on a superseded task counts as
  satisfied once **its replacement** is satisfied, recursively, and Delivery treats
  `superseded` exactly like `cancelled`: not a blocker, never confirmable by a review, never
  audited for paths.
- **An honest scope report becomes a captain decision instead of a failure.**
  `agent_teams_update_task` completing an `implementation`/`repair` task with a path outside
  `inScope` no longer fails the lane: the gate reports **every** undeclared path at once and
  the task is held in **`awaiting_scope_review`** with its evidence. The captain then accepts
  the paths with the new **`agent_teams_accept_paths`** (additive, never a replacement;
  completes the lane in the same call once the widened scope covers the report), reassigns it
  (`reassign_task`) or replaces it (`supersede_task`). `accept_paths` also works **post-hoc**
  on a completed task until a review/requirements verdict freezes the contract, and `force`
  overrides that freeze. A path that is in `inScope` *and* matches `outOfScope` remains a hard
  failure: that is a contradictory contract, not a scope decision.
- **`taskPlanning.sharedInScope`.** A profile may declare paths that every
  `implementation`/`repair` task inherits (`sharedInScope: ['docs/CHANGELOG.md', 'tools/']`);
  they are merged into `inScope` at creation and excluded from the overlap comparison, so two
  sibling lanes may both touch generated docs without a false conflict. The string form of
  `taskPlanning` keeps working, and an unknown key inside the object is rejected with the fix.
- **Known deltas: `agent_teams_pin_delta` / `agent_teams_unpin_delta`.** A check that is red in
  this workspace for a reason outside the lane is pinned once (`check`, `expected`, `reason`;
  `check` is the identity, so a duplicate is refused by name). A `waived` command or criterion
  that carries no evidence is then filled in as `pinned delta <id>: <reason> (expected: …)`
  instead of every lane inventing the same reason; an unpinned waiver without its own evidence
  stays rejected. The registry is printed by `agent_teams_status` under `Known deltas`.
- **`reviewPolicy.requiredReviewers` is enforced.** Delivery requires, for every listed entry,
  a completed review with `verdict=pass` from a reviewer whose member name equals the entry or
  whose role contains it (`correctness` matches `correctness-reviewer`). A review the captain
  owns satisfies nobody. An absent list changes nothing, so no existing team is retroactively
  blocked.
- **Panel.** `awaiting_scope_review` shows its own status label and reads as in-flight work;
  `superseded` gets a faded striped grey tone (dead but dealt with, not red) with its own
  label in both locales.

## Compatibility

The supported Harness matrix is unchanged: recommended `0.1.5-rc.1`, plus `0.1.2-rc.1`,
`0.1.2-alpha.5`, and `0.1.2-alpha.2`.

`team.json` files written by earlier versions load unchanged. The new fields are optional on
read (`supersededBy`, `knownDeltas`, `profile.sharedInScope`), the two new statuses are
additions rather than renames, and a team with no `reviewPolicy.requiredReviewers` keeps its
previous Delivery behaviour. Existing tool signatures only gained optional parameters. The
four new tools are `agent_teams_supersede_task`, `agent_teams_accept_paths`,
`agent_teams_pin_delta` and `agent_teams_unpin_delta`.

**Upcoming in 0.1.24:** every team-scoped tool will take a mandatory `team_id`, except
`agent_teams_create` (which returns it) and `agent_teams_status` called with no arguments
(which lists the caller's teams). A team created earlier keeps working, because its existing
id *is* the `team_id`.

Update the plugin in your existing profile, then restart Harness:

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.1.23
```

See [release verification](https://github.com/WhiteWh/dsh-agent-teams/tree/agent-teams-hardening/docs/releases/v0.1.23) for the verification matrix, the artifact digest and the deployment/rollback record.
