# AgentTeams v0.2.2

A panel-and-contract release on top of 0.2.1, requested by the owner after living with the
phase board and the members list: **the panel is now one graph view over one compact
roster**, and a plan that declares phases renders every task it declares.

## What changed for the reader

- **A member row is one compact line.** Portrait, role symbol (the role in words moved into
  its tooltip), name, model badge, action symbol with its state label and the member's task
  chips, ending in the animated work plaque. The retired second and third lines — the role
  words and the long "working on tN" sentence — are gone with their locale keys, so a
  twelve-member team reads as twelve lines instead of thirty-six.
- **Inside a phase, sequential work is a line.** The board gives each task its chain depth
  inside its own phase: work that runs in sequence reads as one row, parallel work takes its
  own row, and the phase column stretches to the width of its longest chain. A chain edge is
  now a short forward curve inside the row instead of a long curve between columns.
- **A cancelled node is a pale scarlet hatched card** — settled history, not an alarm — so it
  no longer competes with the error colour of a failed task.
- **The Tree and Queues views are gone**, together with their model projections and their
  locale keys. The phase board carries the graph, the checklist under it carries the flat
  list, and the progress block is one bar again instead of one row per phase. The snapshot
  still publishes `progress.byPhase` for other clients; no panel row renders it.

## Also fixed

- **A fully declared plan rendered an empty board.** `phaseColumns` returned the declared
  columns only when some task was left unphased, so a plan whose phases covered every task
  fell through to the DAG levels — which then had nothing to lay out. This was shipped in
  0.2.1 and is fixed here, with a check on both halves of the rule.
- **Two stylesheet classes were rendered without a rule** (`css.viewHint` on the board's
  footnote, `css.archivedWrap` on an archive card). The footnote has its own rule now, the
  dead class reference is gone, and a new check fails whenever a `css.<name>` a panel
  component renders has no rule in its stylesheet.

## Compatibility

No state, tool, schema, profile key or quality gate changed: this release ships the client
bundle and the client's model module. A stored `team.json`, a profile and every tool call
behave exactly as in 0.2.1, and the supported Harness matrix is unchanged (recommended
`0.1.5-rc.1`).

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.2.2
```

Then restart Harness and refresh the page — a browser that already has the panel open keeps
the old bundle until it reloads.

See [release verification](https://github.com/WhiteWh/dsh-agent-teams/tree/agent-teams-hardening/docs/releases/v0.2.2) for the verification matrix, the artifact digest and the deployment record.
