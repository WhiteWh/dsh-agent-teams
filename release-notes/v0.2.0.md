# AgentTeams v0.2.0

The release that closes the hardening plan: **a running plan can be repaired instead of
rebuilt, several teams are usable at once, and every team's progress is visible in one
number**. Nineteen tools (one new), no renamed tool, and every earlier `team.json` still
loads.

- **Repair a live plan with one batch.** `agent_teams_replan` (captain-only) applies an
  atomic batch — `add_task`, `update_task` (with `retry` and `invalidate`),
  `supersede_task`, `cancel_task`, `accept_paths`, `amend_task`, `move_phase` — under one
  reason. The applier works on a copy of the team, so a single invalid operation (a
  dependency cycle, an unknown id, a contract that cannot pass) leaves the team exactly as
  it was. This replaces the cancel-and-recreate cascade that used to throw away every
  satisfied dependency and every member's context.
- **`invalidate: true` is the explicit permission to touch a lane a member holds.** The
  attempt is revoked, that member is drained, goes `idle` (its session stays) and receives
  `task tN replanned: <reason>` in its mailbox. A capability the plan revoked is refused
  afterwards even while the task is `pending` again, so a late update can never start a new
  attempt on a replanned lane. Members whose only work disappeared go `idle`; nothing is
  retired (that stays exclusive to `remove_member`).
- **The plan is an entity.** `TeamState.plan` carries a monotone `revision` (bumped by
  every graph mutation) plus optional declared phases (`taskPlanning.phases`,
  `create_task phase`, `move_phase`), and every batch appends an
  `agent-teams/plan-revised` event with the diff (`added`, `removed`, `rebound`,
  `invalidated`).
- **Progress you can trust.** One server-computed percentage per team
  (`Σ weight(completed) / Σ weight(total − cancelled − superseded)`, with an already-repaired
  failure treated like a dead lane), reported by the panel, the conversation card and the
  `agent_teams_status` text at the same time: `Progress: 62% (8/13; running 2, blocked 1,
  failed 0, waived 1)`. Both weightings travel in the payload — `byKind` (implementation 3,
  repair 2, the rest 1) and `equal` — `taskPlanning.weights` picks the default and the panel
  switches it. Every task also carries a checkbox glyph (`[x]`/`[~]`/`[ ]`/`[!]`).
- **A task checklist and a running-mode editor.** A collapsible list of every task in
  phase-then-depth order (status glyph, id, subject, kind/round, assignee, status, waivers,
  `→ tN` for a superseded lane) whose rows pin the node in the dependency tree; and a
  running-plan editor that posts the same replan batch to `POST /plan` with
  `action: 'replan'`, including the explicit "stop that member first" box.
- **Several teams at once.** The panel switches teams — one tab per live team (name,
  `done/total`, activity dot) and one team's DAG, members, progress and slices at a time —
  instead of stacking every graph into one column. The scheduler sweeps every live team of
  every workspace, and four fuses are profile config with defaults:
  `maxTeamsPerWorkspace` 4, `maxTeamsPerSession` 8, `maxWorkersPerTeam` (the roster cap),
  `maxConcurrentWorkersGlobal` 8. The worker fuses live on the dispatch primitive, so the
  sweep, a single-team kick and the `agent/status` idle wake-up all obey them.
- **The report answers "who is working".** `agent_teams_status` names the slot holders and
  the queue (`Slots: 1/4 working (worker t2); 3 queued`), lists the limits in force and
  carries the same summary as data (`slots.*`, `limits.*`).

## Compatibility

The supported Harness matrix is unchanged: recommended `0.1.5-rc.1`, plus `0.1.2-rc.1`,
`0.1.2-alpha.5`, and `0.1.2-alpha.2`.

`team.json` files written by earlier versions load unchanged — every new field (`plan`,
`progressWeights`, `sharedInScope`, `supersededBy`, `knownDeltas`, …) is optional on read,
and no status or tool was renamed. Two changes need attention when integrating directly
against the tools:

- every team-scoped tool takes a `team_id` (since 0.1.24; a member of exactly one team may
  still omit it);
- a completed contract stays immutable — `amend_task force` overrides a post-review
  *freeze*, and the post-hoc repair for a finished lane is `accept_paths`.

The tool set grew from 18 to 19 (`agent_teams_replan`).

## Upgrade

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.2.0
```

Then restart Harness for that profile and refresh the browser. New profile keys
(`maxTeamsPerWorkspace`, `maxTeamsPerSession`, `maxWorkersPerTeam`,
`maxConcurrentWorkersGlobal`) are optional; omitting them keeps the defaults above.

See [release verification](https://github.com/WhiteWh/dsh-agent-teams/tree/agent-teams-hardening/docs/releases/v0.2.0) for the verification matrix, the artifact digest and the deployment record.
