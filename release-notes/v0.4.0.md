# AgentTeams v0.4.0

The release that answers the Φ1 feedback from the dx9 run (183 tasks, 11 members, two
phases closed) and the material-layers report before it. Nine defects, one of them the
largest a person watching the work can feel: **the graph now speaks the plan's own
vocabulary**.

## The plan's vocabulary reaches the graph

- **A phase declares itself on first use.** `create_task(phase: 'Φ2', phase_title: 'Φ2 — light')`
  now declares that phase on a running team instead of refusing it: the run produced **209
  tasks with no phase at all**, because the only declarer was a `replan` `move_phase` and
  that tool had died for the team. A staged plan stays strict — its phases belong to the plan.
- **Every lane can carry the plan's own id.** `label` (`G.4`, `P4.3`, `L.2`) is accepted by
  `create_task` and by a replan `add_task`, and is shown beside the plugin's `t147` on the
  board, in the checklist and in the status text.
- **A phase rolls itself up.** `Φ2 — light: 4/12 done · 1 failed · 1 verified` is printed in
  the report (`Phases (…)` before the task list) and in the board's column header, from the
  same host-side counts.
- **`verified` is its own state.** A lane a passing review or verification judged is marked
  (a `✓` on its node, `· verified` in the report) and counted per phase, so the brief's
  `landed` versus `verified` is readable without asking the captain.

## Defects fixed

- **A replaced member session no longer disables the batch tools** (F1). The whole-plan
  validation required an active owner for *every* task, including the history a replaced
  member left behind — and since a terminal task cannot be reassigned and a removed name
  cannot be re-added, `cancel_task`, `move_phase`, `close_phase` and multi-task repair were
  lost for the rest of the phase. Settled tasks are history now; `retry`, the only path that
  revives one, refuses without a new owner.
- **A member removal requeues only live work** (F3). It skipped only `completed`, so
  `invalidateTaskAttempt` resurrected failed, cancelled and superseded lanes into the pool —
  six of eight entries in the field, one of them putting a second writer on a file a live
  lane was editing.
- **The dispatch cap counts work, not a recorded status** (material-layers item 2). The cap
  read `member.status`, a field written from the host's `agent/status` stream: one missed
  idle event made a team of idle members look full and `kickTeam` returned before
  dispatching anybody, team-wide. Lanes then waited for a manual message. Measured RED
  `spawns=0 status=pending` → GREEN `spawns=1 status=claimed`.
- **The status report is bounded** (F6). It echoed every task with its output — 64 432
  characters on the run's shape, and the session crashed on it twice. Now 1 518: the work
  that needs attention, the settled history counted but not printed, its outputs dropped,
  with `live`/`task_id`/`since`/`include_output` to reach everything.
- **A stale handoff marker can be released** (F2). `update_task {invalidate:true}` on a task
  nobody could drain left `reassigning` set forever; `claim_task` answered "wait for the
  handoff to finish" and `reassign_task` "already being reassigned", with supersede as the
  only exit. `release: true` clears it (and refuses, pointing at `invalidate`, when a member
  really holds the lane).
- **A replacement may inherit its lane's paths** (F4). `supersede_task` validated the inline
  replacement against the task it replaces before the link serializing them existed; the
  replaced task now counts as serialized for the duration of the call.
- **`inScope` wildcards are expanded** (F4b). `C_Core/shaders/**` was compared literally, so
  a lane's four real files read as outside its contract and two lanes sat in
  `awaiting_scope_review`. `**` spans directories, `*`/`?` stay inside one segment.
- **A `work` lane's waiver can be discharged** (F5). `kind=review` accepted only an
  implementation/repair/verification/integration target, so a work lane that honestly
  reported a waived command against a pinned delta could never be confirmed.

## Also in this release

The round-3 panel work of 0.3.0 (three-row work plaque, collapsible phases, a large member
node folding into a tray), the freeze hotfix (the chain walk is memoised: 130 s → 0.4 ms on
a 56-task layered phase) and `PanelErrorBoundary`, which keeps a panel fault from unmounting
the shell.

## Compatibility

State and tool behaviour changed; every new field is optional and older `team.json` files
load unchanged:

- `replan` takes one more operation (`close_phase`) and one more flag (`release`); its
  result prints a change line without a task id for a phase-scoped operation;
- `create_task` accepts `label` and `phase_title`, and declares an unknown phase on a
  running team;
- `team.json` may carry `tasks[].label`, `tasks[].origin`, `plan.phases[].closed`/`closedAt`
  and `plan.phases[].title`;
- the snapshot may carry `label`, `verified`, `progress.segments`, `progress.byPhase` counts
  and `plan.phases[].closed`;
- `agent_teams_status` is bounded by default (see above) — pass `live: false` for the old
  full listing;
- no tool was renamed, no status added, no quality gate loosened, and the supported Harness
  matrix is unchanged (recommended `0.1.5-rc.1`).

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.4.0
```

Then restart Harness and refresh the page — a browser that already has the panel open keeps
the old bundle until it reloads.
