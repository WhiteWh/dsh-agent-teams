# AgentTeams v0.1.22

- Fixed the activity panel showing the **previous artwork pack** after an upgrade. The panel addresses its images by file name, and those names survived the redraw from the whale pack to the amber terminal pack — `member-engineer-v2.png` was the whale and is now the terminal. The host route serves them with `cache-control: public, max-age=86400`, so a browser that had cached the old bytes kept drawing them for a day and a freshly deployed panel looked unchanged (reported from a real deployment: a 0.1.21 profile still rendered the whale captain).
- Every artwork URL now carries a content revision: `?v=<pack revision>`, where the revision is derived from the packaged bytes themselves. Redrawing a pack produces a different URL, so the browser refetches immediately instead of waiting out a cache lifetime, and no manual cache-busting step is involved.
- `src/client/art-revision.ts` holds the revision. It is generated by `node scripts/art-revision.mjs --write`, and it cannot silently go stale: `pnpm build` and `scripts/verify.mjs` both re-derive the value from `assets/agent-teams/` and fail with `artwork revision is stale: committed …, pack …`. Swapping an icon without regenerating the revision is now a build failure, not a stale panel.
- The artwork route moved into `src/artwork.ts` so the request path it actually serves is testable: it reads the URL path only (the `?v=` query is ignored, never treated as part of the file name) and still serves allowlisted names exclusively, which keeps an unknown name or a traversal attempt a plain 404.
- Five new offline checks cover the pair: the committed revision describes the packaged bytes, a redrawn file changes the revision, every URL the client builds carries the revision, the route ignores the query while returning the exact packaged bytes with the unchanged `image/png` and day-long caching headers, and the route still rejects unlisted names, `../package.json` and `%2e%2e%2fpackage.json`. The route checks were mutation-tested: reading the name from the raw request URL (the naive implementation) fails the suite.
- The member portrait now carries **one** corner mark instead of two. The role symbol was redundant next to a row that already names the role in words, so the avatar keeps only the live action mark; the captain avatar drops its role mark too. The role symbol became the **compact** mark instead: it is drawn at 12 px in the slots where neither the mascot nor a label fits — the task-detail assignment line and a Queues row — resolved through one `ownerSymbolUrl()` helper (the captain owner gets the lead mark, an unclaimed task or an unmatched role keeps the coloured dot), and the collapsed panel pill now shows the action symbol rather than a plain dot. Three checks hold the shape: the avatar renders the activity mark and no role mark, the role pack still resolves for every role plus the lead, and the compact surfaces draw the symbol packs with their fallback intact.
- The dependency boards (**Tree** and **Phases**) keep their node heads text-only: a 12 px role mark beside a 9.5 px task id was the least readable spot in the panel, so the two node heads keep the small dot they had and the assignment is named in the task-detail line below the board.
- The **Phases** view scrolls as one board. Its phase titles used to live in a separate horizontal scroller from the node canvas, so a scrolled header row drifted away from the columns it named; headers and canvas now share one scroller and each header sits at the exact `x` the layout gave that column's nodes.
- The **Agents** view is gone. The member tree above already carries the same roster, states and per-member task buckets, so the panel now offers the tree plus two read-only cuts (**Phases** and **Queues**); a browser that had stored the removed view falls back to the tree instead of showing an unselected tab, and its locale keys were dropped rather than left dangling.
- In the members tree the portrait now spans the **whole block**: the assignment line is a row of the same row element, so the icon reaches the `Captain assigned` line instead of stopping above it and leaving half a column empty. The portrait is capped at 76 px, and the narrower text column yields the role text before the member name, which keeps its width.

## Compatibility

The supported Harness matrix is unchanged: recommended `0.1.5-rc.1`, plus `0.1.2-rc.1`, `0.1.2-alpha.5`, and `0.1.2-alpha.2`.

`team.json` is untouched: no state field, no tool signature and no quality-gate rule changed in this release. A browser that cached artwork under the old URLs stops being asked for them, so the upgrade shows the current pack without clearing anything by hand.

This release is a packaging fix and takes the `0.1.22` slot, so the plan's later releases shift by one: the contract work (`amend_task` extensions, `retry` from `failed`, `superseded` with an atomic dependency redirect, post-hoc path acceptance, the known-delta registry, `requiredReviewers` enforcement) ships in **0.1.23**, mandatory `team_id` addressing in **0.1.24**, and the plan progress, task checklist and live-team replanning in **0.2.0**.

Update the plugin in your existing profile, then restart Harness:

```sh
dsh plugin --profile <your-profile> add --save-exact @nanmicoder/dsh-agent-teams@0.1.22
```

See [release verification](https://github.com/WhiteWh/dsh-agent-teams/tree/agent-teams-hardening/docs/releases/v0.1.22) for the verification matrix, the mutation evidence, the artifact digest and the deployment/rollback record.
