WP2: amend the whole contract, legalize the retry from failed (S08)

Feedback section 1: the amendment covered five contract fields, rejected every
kind=work task and treated `failed` as immutable, so a wrong brief or a red lane
still ended in cancel-and-recreate.

Rule (src/quality-gates.ts, src/state.ts, src/types.ts):
- ContractAmendmentInput gains deliverables, nonGoals, reviewedTaskId, subject and
  description. A quality task amends the whole contract; a work task amends
  subject/description/deliverables/nonGoals and is rejected by name when a quality
  field is attempted.
- reviewedTaskId must exist, must not be the task itself, and must point at an
  implementation/repair/verification/integration task.
- `failed` is amendable (the first retry step); completed and cancelled stay
  immutable. TASK_TRANSITIONS.failed is now ['pending'] - the move reassign_task
  already made through invalidateTaskAttempt - so transitionError and
  evaluateQualityCompletion stop disagreeing with the tools.
- amendTaskContract takes `force` and returns invalidatedReviews: the forced
  override of a post-review freeze marks the passing verdict `stale` (new durable
  ReviewVerdict), which is deliberately absent from the member-facing update_task
  enum and can only be produced by the amendment.

Tools (src/tools.ts):
- agent_teams_amend_task exposes the new payload plus force, applies the staled
  verdicts inside the same team lock and returns staled_reviews.
- A running team's update_task accepts dependencies/assignee edits for pending (any
  attempt) and failed tasks; claimed/in_progress still refuse (that edit is WP4/S10
  replan with attempt invalidation).
- agent_teams_status prints `revised xN` for an amended contract.

Tests first: the amend suite failed 5 of its 15 cases, the transition-table matrix
and the new failed-retry label failed, and the lifecycle scenario died at
"task t1 is failed; terminal contracts are immutable". Green now: amend 15/15,
quality-gates-tdd 108 PASS/0 FAIL, lifecycle all checks passed (new scenario
captain undercounts inScope -> member refused -> lane failed -> amend -> retry ->
completed on the same task id), verify.mjs 230 PASS/0 FAIL with four new checks.
All 21 suites and both policy checks exit 0.

Two honest test adaptations: the retry assertion no longer demands
status === 'pending' (reassign_task returns after kicking the member, so the task
may be dispatched again) and the lifecycle block reads its own team instead of the
shared lifecycle-bound helper.

Docs: docs/quality-gates.md gains section 1.4, the stale verdict in the enum and
the legalized retry in the state-machine row.
